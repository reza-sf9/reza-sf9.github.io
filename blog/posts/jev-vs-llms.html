Jev vs LLMs: when you need a decision, not a paragraph

October 26, 20266 min read

Almost every model I've built ends in a decision. Should a visiting nurse refer this wound to a specialist? Is this pressure ulcer stage II or stage III? Is this diabetic foot ulcer infected? For the last few years I've used large language models for questions like these, which means asking for an answer in words and then writing code to pull the decision back out of the words.

In September 2026, TypeSafe AI introduced Jev, a model built around the opposite idea: skip the words and return the decision. Here is how it differs from an LLM, where I think it could fit in clinical AI, and what I'd want to check before trusting it.

What Jev is

TypeSafe calls Jev the first of a new class it names System One Models, after Kahneman's fast, intuitive System 1 thinking. You give Jev a state, which is text or JSON, and one or more typed questions about it. Each question comes back as a value your code can use directly:

  • Choice: one option from a list you define, with a probability for every option and a confidence.
  • Score: a rating of the state against a rubric.
  • Noul: a value between 0 and 1 for whether a statement is true.

According to TypeSafe, Jev scores all options in parallel instead of generating token by token, and it is trained with a method the company calls Reinforcement Learning for Calibrated Decisions (RLCD), which rewards honest probabilities rather than convincing text. The company describes it as "a frontier-intelligence function call."

Why it caught my attention

In my work on home wound referral, the hard part was never getting a model to say "refer." It was the plumbing around it: forcing the output into a fixed set of labels, handling answers that didn't parse, and deciding what to do when the model wasn't sure. A typed choice with probabilities removes most of that plumbing.

Confidence is the bigger deal. In triage, a well-calibrated "60% sure" is more useful than a confident wrong answer, because it tells you when to hand the case to a person. Jev's design turns that into a setting: choose a confidence threshold for acting automatically, and send everything below it for review. That is exactly the shape of a clinical decision-support workflow.

Where LLMs still win

Jev doesn't write, and that's deliberate. But in healthcare, the explanation is often the product. When we built FT-ARM, the agentic reflection loop and its written rationale were what made a pressure ulcer grade worth a clinician's attention. A probability vector doesn't tell a wound nurse which tissue features drove the call.

LLMs also handle open-ended, multi-step reasoning. Jev's documentation says questions should be atomic, the kind of call a knowledgeable person could make in seconds, and that anything needing extended reasoning should be broken into smaller questions and combined in code.

What I'd test before trusting it in a clinic

  • Calibration on clinical data. TypeSafe's evaluations compare Jev against an average of two frontier LLMs on workflows its own team wrote, and the company notes that this could be biased. I'd want reliability diagrams and expected calibration error on held-out patient data, including after a change of site or camera.
  • What "can't hallucinate" means. TypeSafe is upfront that its 0% hallucination figure comes from the schema guarantee, not from an experiment. Jev can't return an invalid answer, but it can still pick the wrong valid one.
  • Images. Wound assessment starts from a photo. Jev 1.14 added image inputs as an experimental feature, and TypeSafe itself says those features aren't ready for production yet.
  • Privacy and deployment. Patient data needs a clear answer on where it is processed and how long it is kept.

My take

I don't see Jev as an LLM replacement. I see a split: models like Jev make the many small, fast, auditable decisions inside a workflow, and LLMs or vision-language models explain the few that a person needs to review. For wound care, that could mean a fast typed referral decision for every photo, with a written rationale generated only for uncertain or high-risk cases.

The experiment I'd like to see is simple: give Jev and a fine-tuned multimodal LLM the same pressure ulcer staging task, and compare not only accuracy but calibration and cost per correct decision. If the calibration holds up on clinical data, this could change how decision-support systems are built.
